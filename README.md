# 車両月報作成アプリ

社員が毎日の車両利用後に簡単な入力を行い、月末に車両ごとの月報として一覧・CSV出力できる社内向けアプリです。

## 技術構成

- Next.js 14（App Router） + TypeScript
- SQLite（ローカル開発） / PostgreSQL（クラウド公開時）+ Prisma
- Tailwind CSS

## 1. セットアップ方法（ローカル）

```bash
npm install
npm run db:push
npm run db:seed
```

## 2. 起動方法

```bash
npm run dev
```

http://localhost:3000 を開いてください。

## 3. データベース初期化方法

```bash
npm run db:reset
```

---

## 4. 画面構成

| 画面 | パス | 内容 |
|---|---|---|
| トップ画面 | `/` | 各機能への入口メニュー |
| 日報入力画面 | `/nippo` | 日付・部署・車両（部署で絞り込み可）・訪問先（複数可・マイリスト機能あり）・終業時メーター・給油場所（任意・マイリスト機能あり）・給油量（任意）・備考を入力 |
| 月報一覧画面 | `/geppo` | 年月・車両で絞り込み、車両別×日付順に一覧表示（アコーディオン開閉）。編集・削除・CSV出力 |
| 車両管理画面 | `/vehicles` | 車両・所属の登録・編集・削除（管理者パスワードが必要） |

## 5. 実装時に置いた前提・仕様判断

- **訪問先の保存方法**：改行区切りの1つの文字列として保存。CSV出力時は「、」区切りでまとめる。
- **運転者機能は廃止**：1人1台のスマホ・パソコンで使う想定で、「前回選んだ車両」は端末（ブラウザの`localStorage`）ごとに記憶する。
- **日報登録後の画面遷移**：登録成功後はトップ画面に戻り「入力されました」を表示（メーター警告があれば併記）。
- **入力クリア時の確認**：「入力をクリア」ボタンにも削除操作と同様の確認ダイアログを表示する。
- **メーターの逆行チェック**：直近の記録より入力値が小さい場合は警告を表示するが、登録・更新自体は必ず成功させる。
- **車両・所属の削除の扱い**：利用記録・紐づく車両が既に存在する場合、削除は行わず自動的に「使用停止（非表示）」に切り替える。「非表示の車両（使用停止中）」「非表示の所属（使用停止中）」から「復活させる」ボタン1つで元に戻せる。
- **所属（部署）機能**：車両を「所属」でグループ分けできる。アクセス制限は行っておらず、あくまで表示上のグループ分け。日報入力画面には部署の絞り込み専用プルダウンがあり、選ぶと車両プルダウンがその部署だけに絞り込まれる（この端末で最後に選んだ部署も記憶する）。
- **マイリスト（よく使う訪問先・給油場所）**：ログイン機能なしで実現するため、車両の記憶と同様に「端末ごと」に保存する方式（`localStorage`、最大12件・重複除去・最近保存した順）。入力欄の「☆保存」ボタンで保存し、チップ状のボタンから選択、「×」で削除できる。複数端末での共有はできない。
- **月報一覧の並び順・まとめ方**：車両ごとにグループ化し日付の古い順。同じ車両・同じ日に2回以上入力があった場合は1日1行にまとめ（訪問先は連結、終業時メーターは最大値、給油場所は連結、給油量は合計）、「内訳を見る」から個別編集・削除ができる。
- **CSV出力項目**：日付・訪問先・終業時メーター・給油場所・給油量・給油金額・日（1〜31の数字）・備考の8項目。社内Excelの「運転日報」シートに転記しやすい構成。給油金額は常に空欄（Excel側で手入力）。月の全日を出力し、入力のない日は空欄の行にする。車両を絞り込んでいない場合は車両ごとにブロックを分けて出力する。
- **通信エラー時の表示**：各画面でデータ取得・登録・更新・削除の通信に失敗した場合、「通信エラーが発生しました」というメッセージと再読み込みの導線を表示する。
- **ログインの有効期間**：合言葉ログイン（`APP_PASSWORD`・管理者パスワード共通）のCookie有効期限は365日に設定している（`src/lib/auth.ts` の `AUTH_COOKIE_MAX_AGE`）。ただし、iPhoneでホーム画面に追加して使っている場合、iOS側の仕様（Safariの「非対話ストレージの削除」機能）により、実際にはおよそ7日間アプリを開かないとログイン情報が消えてしまうことがある。これはアプリ側の設定では回避しきれないOS側の制限であり、頻繁にパスワードを求められる場合はSafariのブックマークから開く運用に変更することで軽減できる可能性がある。

## 6. パスワード保護（クラウド公開時）

環境変数 `APP_PASSWORD` を設定すると、アプリ全体に共有パスワードでのログインを求める（未設定時は保護なし）。

車両管理・所属管理には別途、管理者パスワードが必要（既定値 `mIck3216`、変更する場合は環境変数 `ADMIN_PASSWORD`）。

---

## 7. クラウドに公開する場合（Vercel）

1. GitHubにアップロード
2. Vercelでプロジェクトを取り込む
3. 「Storage」から「Prisma Postgres」を接続（`DATABASE_URL` 自動設定）
4. 環境変数 `APP_PASSWORD`・`SEED_SECRET`（初回のみ）・必要なら `ADMIN_PASSWORD` を設定
5. 再デプロイ
6. 初回のみ `https://あなたのURL/api/admin/seed?key=SEED_SECRETの値` でサンプルデータ投入（任意）

---

## 8. iPhoneでアプリのように使う

Safariで開き、「共有」→「ホーム画面に追加」。ただし上記5章の「ログインの有効期間」の注意点を参照。
