# 車両月報作成アプリ

社員が毎日の車両利用後に簡単な入力を行い、月末に車両ごとの月報として一覧・CSV出力できる社内向けアプリです。

## 技術構成

- Next.js 14（App Router） + TypeScript
- SQLite（ローカル開発） / PostgreSQL（クラウド公開時）+ Prisma
- Tailwind CSS

Next.js の Route Handler（`src/app/api/**`）をそのままAPIサーバーとして使う構成です。

---

## 1. セットアップ方法（ローカルで動かす場合）

### 必要環境

- Node.js 18.18 以上（20系推奨）
- npm

### 手順

```bash
npm install
npm run db:push
npm run db:seed
```

---

## 2. 起動方法

```bash
npm run dev
```

ブラウザで [http://localhost:3000](http://localhost:3000) を開いてください。

---

## 3. データベース初期化方法

まっさらな状態に戻したい場合：

```bash
npm run db:reset
```

これはDBを再作成し（`prisma db push --force-reset`）、サンプルデータを再投入します（`npm run db:seed`）。

## 4. 画面構成

| 画面 | パス | 内容 |
|---|---|---|
| トップ画面 | `/` | 各機能への入口メニュー |
| 日報入力画面 | `/nippo` | 毎日使うメイン画面。日付・車両（所属ごとにグループ表示）・訪問先（複数可）・終業時メーター・給油場所（任意）・給油量（任意）・備考を入力 |
| 月報一覧画面 | `/geppo` | 年月・車両で絞り込み、車両別×日付順に一覧表示（車両ごとにアコーディオン開閉）。編集・削除・CSV出力 |
| 車両管理画面 | `/vehicles` | 車両・所属の登録・編集・削除（管理者パスワードが必要） |

### API（Route Handler）

| メソッド | パス | 内容 |
|---|---|---|
| GET / POST | `/api/vehicles` | 車両一覧取得 / 新規登録 |
| PUT / DELETE | `/api/vehicles/:id` | 車両更新 / 削除（利用記録がある場合は自動的に非表示化） |
| GET / POST | `/api/departments` | 所属一覧取得 / 新規登録 |
| PUT / DELETE | `/api/departments/:id` | 所属更新 / 削除（紐づく車両がある場合は自動的に非表示化） |
| GET / POST | `/api/logs` | 利用記録一覧取得（絞り込み対応） / 新規登録 |
| PUT / DELETE | `/api/logs/:id` | 利用記録更新 / 削除 |
| GET | `/api/logs/last-meter` | 指定車両の直近メーター取得 |
| GET | `/api/logs/csv` | 月報のCSVダウンロード |
| POST | `/api/login` | アプリ全体の合言葉ログイン |
| GET / POST | `/api/admin-login` | 車両管理用の管理者パスワード確認・ログイン |
| GET | `/api/admin/seed` | クラウド公開後、初回のみ使うサンプルデータ投入 |

## 5. 実装時に置いた前提・仕様判断

- **訪問先の保存方法**：改行区切りの1つの文字列として保存。CSV出力時は「、」区切りでまとめる。
- **運転者機能は廃止**：1人1台のスマホ・パソコンで使う想定で、「前回選んだ車両」は使っている端末（ブラウザの`localStorage`）ごとに記憶する。
- **日報登録後の画面遷移**：「登録する」を押して保存に成功すると、トップ画面に戻り「入力されました」というメッセージを表示する（メーター警告があれば併記）。
- **入力クリア時の確認**：「入力をクリア」ボタンを押すと、削除操作と同様の確認ダイアログを表示してから消去する。
- **メーターの逆行チェック**：同じ車両の直近の記録より入力値が小さい場合は警告を表示するが、登録・更新自体は必ず成功させる。
- **車両・所属の削除の扱い**：利用記録（車両）や紐づく車両（所属）が既に存在する場合、削除は行わず自動的に「使用停止（非表示）」に切り替える。車両管理画面には「非表示の車両（使用停止中）」「非表示の所属（使用停止中）」という小さな一覧があり、「復活させる」ボタン1つで元に戻せる。
- **所属（部署）機能**：車両が増えてきた際に一覧が見づらくならないよう、車両を「所属」でグループ分けできるようにしている。所属ごとのアクセス制限（見える・見えないの制御）は行っておらず、あくまで表示上のグループ分けのみ。全員が同じ合言葉でアプリ全体・全車両にアクセスできる点は従来通り。
  - 所属マスタは車両管理画面の「所属の管理」（折りたたみ式）から登録・編集・削除する。
  - 車両を登録・編集する際、所属を選択できる（未設定の場合は「未分類」として扱われる）。
  - 日報入力画面の車両プルダウン、月報一覧の車両プルダウンは、いずれも所属ごとにグループ表示される。
  - 車両管理画面の一覧も、所属ごとにグループ表示される。
- **月報一覧の並び順・まとめ方**：車両ごとにグループ化し、グループ内は日付の古い順。同じ車両・同じ日に2回以上入力があった場合は1日1行にまとめて表示し（訪問先は連結、終業時メーターは最大値、給油場所は連結、給油量は合計）、「内訳を見る」ボタンから元の入力ごとに個別編集・削除ができる。
- **CSV出力項目**：日付・訪問先・終業時メーター・給油場所・給油量・給油金額・日（1〜31の数字）・備考の8項目。社内で使用しているExcelの「運転日報」シートにそのまま転記できるよう、この項目・並び順にしている。
  - 「給油金額」は入力画面には項目がなく、常に空欄（Excel側で手入力する想定）。
  - 実際に入力された日だけでなく、選択した月の1日〜末日をすべて出力し、入力のない日は空欄の行にする（月末の月報にそのままコピペできるように）。
  - 車両を絞り込んでいない場合は、車両ごとにブロックを分けて（見出し行＋全日分）続けて出力する。
- **通信エラー時の表示**：日報・月報・車両管理の各画面で、データ取得や登録・更新・削除の通信に失敗した場合、画面が固まらず「通信エラーが発生しました」というメッセージと再読み込みの導線を表示する。

## 6. パスワード保護（クラウド公開時）

環境変数 `APP_PASSWORD` を設定すると、アプリ全体に共有パスワードでのログインを求めるようになります（未設定時はローカル開発同様、保護なし）。

車両管理・所属管理（登録・編集・削除）には、これとは別に専用の管理者パスワードが必要です。既定値は `mIck3216` です。変更したい場合は環境変数 `ADMIN_PASSWORD` を設定してください。車両・所属の一覧を見るだけ（日報・月報での選択肢表示）には管理者パスワードは不要です。

---

## 7. クラウドに公開する場合（Vercel）

1. GitHubにこのプロジェクトをアップロードする
2. Vercelでプロジェクトを取り込む
3. Vercelの「Storage」タブから「Prisma Postgres」を接続する（`DATABASE_URL` が自動設定される）
4. 環境変数 `APP_PASSWORD`・`SEED_SECRET`（初回のみ）・必要なら `ADMIN_PASSWORD` を設定する
5. 再デプロイする
6. 初回のみ、`https://あなたのURL/api/admin/seed?key=SEED_SECRETの値` を開いてサンプルデータを投入する（任意）

Prisma Postgresは無料の範囲で、このアプリの規模であれば十分収まります。

## 8. iPhoneでアプリのように使う

ホーム画面に追加すると、専用アイコンで開けます（`public/manifest.json` と `src/app/layout.tsx` で設定済み）。Safariで開き、「共有」→「ホーム画面に追加」を選んでください。
