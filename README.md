# 車両月報作成アプリ

社員が毎日の車両利用後に簡単な入力を行い、月末に車両ごとの月報として一覧・CSV出力できる社内向けアプリです。

## 技術構成

指示いただいた構成のまま採用しています（変更なし）。

- Next.js 14（App Router） + TypeScript
- SQLite + Prisma
- Tailwind CSS

このアプリだけの規模であれば、より複雑な構成（別のバックエンドAPIサーバーやORM）にする必要はなく、
Next.js の Route Handler（`src/app/api/**`）をそのままAPIサーバーとして使う構成が最もシンプルで保守しやすいため、
指定いただいた技術スタックをそのまま採用しました。

## 1. セットアップ方法

### 必要環境

- Node.js 18.18 以上（20系推奨）
- npm

### 手順

```bash
# 1. 依存パッケージのインストール
npm install

# 2. データベースの初期化（テーブル作成 + 初期データ投入）
npm run db:push
npm run db:seed
```

`npm install` の際に `postinstall` で `prisma generate` が自動実行されます。

---

## 2. 起動方法

```bash
npm run dev
```

ブラウザで [http://localhost:3000](http://localhost:3000) を開いてください。

本番相当で動かす場合：

```bash
npm run build
npm run start
```

## 3. データベース初期化方法

開発用のSQLiteファイル（`prisma/dev.db`）は `.gitignore` 対象です。まっさらな状態に戻したい場合：

```bash
npm run db:reset
```

これは以下を実行します。

1. DBを一度破棄してスキーマを再作成（`prisma db push --force-reset`）
2. サンプルデータを再投入（`npm run db:seed`）

スキーマ（`prisma/schema.prisma`）を変更した場合は `npm run db:push` を再実行してください。

## 4. 画面構成

|---|---|---|
| トップ画面 | `/` | 各機能への入口メニュー |
| 日報入力画面 | `/nippo` | 毎日使うメイン画面。日付・車両・訪問先（複数可）・終業時メーター・給油場所（任意）・給油量（任意）・備考を入力 |

| メソッド | パス | 内容 |
|---|---|---|
| GET / POST | `/api/vehicles` | 車両一覧取得 / 新規登録 |

| GET | `/api/logs/csv` | 月報のCSVダウンロード（`vehicle-monthly-report_YYYY-MM.csv`） |

## 5. 実装時に置いた前提・仕様判断（要求仕様に明記のなかった部分）

- **訪問先の保存方法**：`vehicle_logs.destination` は改行区切りの1つの文字列として保存しています（別テーブル化はせず）。仕様書にある「初期版では使いやすさと実装の簡単さを優先」という指示に基づく判断です。日報入力画面では「＋訪問先を追加」ボタンで複数行を追加でき、月報一覧では行ごとに箇条書き表示します。CSV出力時は「、」区切りで1セルにまとめています。
- **運転者の廃止と「前回の車両」の記憶方法**：運転者マスタは廃止しました。1人1台のスマホ・パソコンで使う想定のため、「前回選んだ車両」は運転者ごとではなく、使っている端末（ブラウザ）ごとに覚えるようにしています（ブラウザの`localStorage`に保存）。そのため、複数人が同じ端末を共有して使う場合、車両の選択が前の人の使用時のまま残る点にご注意ください。
- **メーターの逆行チェック**：同じ車両の直近の記録（日付が最新のもの）と比較し、入力値がそれより小さい場合は警告メッセージを表示しますが、登録・更新自体は必ず成功させます（要求仕様どおり）。
- **削除の制約**：車両マスタは、既に利用記録が紐づいている場合は削除できないようにし、代わりに「使用停止」への変更を促すメッセージを表示します（データの整合性を保つため）。使用停止にした車両は、日報入力画面のプルダウンには表示されなくなりますが、既存の月報データはそのまま表示されます。
- **月報一覧の並び順**：見やすさを優先し「車両ごとにグループ化 → グループ内は日付の古い順」で表示しています。各行に前回記録との差分（メーター推移）を表示し、逆行している場合は注意アイコンを付けています。車両ごとの表示は開閉できるアコーディオン形式にしています（車両を1台に絞り込んだときはその車両を自動的に開き、「すべて」のときはいったん全部たたんだ状態にしています）。
- **同じ日に複数回入力があった場合のまとめ方**：同じ車両・同じ日に2回以上入力があった場合、月報一覧とCSVでは1日1行にまとめて表示します（訪問先はすべて連結、終業時メーターはその日の最大値、給油場所は連結、給油量は合計）。まとめられた行は「内訳を見る」ボタンから、元の入力ごとに個別の編集・削除ができます。
- **車両管理の管理者パスワード**：車両の登録・編集・削除には、アプリ全体の合言葉（`APP_PASSWORD`）とは別に、専用の管理者パスワードが必要です。既定値は `mIck3216` です。変更したい場合は、環境変数 `ADMIN_PASSWORD` を設定してください（Vercelの場合は「Environment Variables」に追加）。車両の一覧を見るだけ（日報・月報での選択肢表示）には管理者パスワードは不要です。
- **CSV出力項目**：日付・訪問先・終業時メーター・給油場所・給油量・給油金額・日・備考の8項目を出力します（車両名・車両番号は含めません）。社内で使用しているExcelの「運転日報」シートにそのまま転記できるよう、この項目・並び順にしています。
  - 1列目の「日付」は通常の日付表記（例：2026-07-01）です。
  - 「給油金額」は入力画面には項目がなく、常に空欄で出力されます（Excel側で手入力する想定です）。
  - 「給油金額」と「備考」の間にもう1つ「日」列があり、こちらは「1」〜「31」の日番号のみです（Excel側で「給油場所」より右をまとめて貼り付ける際の目印用の列です）。
  - 「備考」は日報入力画面で入力した内容がそのまま出力されます。
- **CSVは月の全日を出力**：実際に入力された日だけでなく、選択した月の1日〜末日（例：7月なら1〜31）をすべて出力し、入力のない日は空欄の行にします。月末の紙・Excelの月報にそのままコピペできるようにするための仕様です。車両を絞り込んでいない場合は、車両ごとにブロックを分けて（見出し行＋全日分）続けて出力します。
- **給油場所・給油量**：どちらも任意項目です。給油量の単位はリットル（L）としています。
- **認証機能**：初期版では未実装です。ただし、後から認証を追加しやすいよう、DBアクセスは全て `src/lib/prisma.ts` 経由・API処理は `src/app/api/**` の Route Handler に集約しています。ログイン機能を追加する際は、各 Route Handler の先頭でセッション確認を行う形で組み込みやすい構成です。
- **クラウド公開時の合言葉（パスワード）保護**：外出先からもアクセスできるようにクラウド（Vercel）に公開する場合、URLを知っていれば誰でもアクセスできてしまうため、簡易的な共有パスワード機能（`APP_PASSWORD` 環境変数）を追加しています。社員ごとのログイン機能ではなく、全員で1つの合言葉を共有する簡易的な保護です。本格的な社員ごとのログイン機能は「今後追加するとよい機能」に記載のとおり、別途実装が必要です。
- **ローカルとクラウドでデータベースの種類が異なる理由**：ローカル開発では手軽なSQLiteを、クラウド公開（Vercel）では常時起動のサーバーではないVercelの仕組み上、ファイルとして保存するSQLiteが使えないため、Vercel Postgres（PostgreSQL）を使うように分けています。そのため `prisma/schema.prisma`（ローカル用）と `prisma/schema.production.prisma`（クラウド用）の2つのスキーマファイルがあります。テーブル構成を変更する際は、両方のファイルを同じ内容に更新してください。

## 6. 今後追加するとよい機能

要求仕様の「今後追加しやすくしておきたい機能」を踏まえた拡張案です。

- ログイン機能（NextAuth.js等を追加し、Route Handlerでセッションチェック）
- 社員ごとの入力制限（ログイン機能とセットで、`VehicleLog` に `userId` を追加）
- Excel出力（`exceljs` 等を追加し、CSV出力と同様の仕組みでルートを追加）
- PDF月報出力（帳票テンプレートを用意し、サーバーサイドでPDF生成）
- 始業時メーターの追加（`VehicleLog` に `startMeter` カラムを追加し、走行距離を自動計算）
- 走行距離の自動計算（`endMeter - startMeter` または前回の `endMeter` との差分を保存）
- 給油量の記録（`VehicleLog` または別テーブルに `fuelAmount` を追加）
- 車検日・点検日の管理（`Vehicle` に `inspectionDate` 等を追加し、期限が近い車両をトップ画面等で通知）
- 管理者承認機能（`VehicleLog` に `approvedAt` / `approvedBy` を追加し、月報確定フローを導入）

## 7. iPhoneでアプリのように使う（ホーム画面に追加）

このアプリは、社内のiPhoneからも「アプリのアイコンをタップして開く」形で使えるように、PWA（ホーム画面追加）対応を組み込んでいます。

### 前提条件

iPhoneから使うには、このアプリを **iPhoneから通信できる場所** で動かしておく必要があります。開発用の `npm run dev` はパソコン自身からしかアクセスできない（`localhost`）ため、社内のiPhoneから使うには以下のいずれかが必要です。

- 常時起動しているパソコン・社内サーバーでこのアプリを動かし、社内ネットワーク経由でアクセスできるようにする
- クラウドの共有可能な環境にデプロイする

このネットワーク周りの設定は会社の環境によって異なるため、情報システム担当の方にご相談ください。

### ホーム画面への追加手順（iPhone / Safari）

1. iPhoneのSafariで、アプリのアドレス（例：`http://社内サーバーのアドレス:3000`）を開く
2. 画面下の「共有」ボタン（四角から矢印が出ているアイコン）をタップ
3. 「ホーム画面に追加」を選ぶ
4. 追加すると、ホーム画面にアイコンが表示され、タップするとアプリのように全画面で開く

### 実装済みの内容

- `public/manifest.json`：アプリ名・アイコン・テーマカラーなどの設定
- `public/icons/`：ホーム画面用アイコン（180px / 192px / 512px）
- `src/app/layout.tsx`：`manifest` の読み込みとiOS向けの `appleWebApp` 設定

## 8. クラウドに公開して、外出先からも使えるようにする

社内のWi-Fiだけでなく、外出先（車の中など）からもiPhone・スマホでアクセスできるようにする手順です。無料の「Vercel（バーセル）」というサービスを使います。むずかしい言葉が多いですが、順番どおりに進めれば大丈夫です。

### 必要なもの（すべて無料）

- GitHubアカウント（プログラムを置いておく場所）
- Vercelアカウント（アプリをインターネット上で動かすサービス）

### 手順1：GitHubにプロジェクトを置く

1. [https://github.com/](https://github.com/) にアクセスし、アカウントをお持ちでなければ新規登録します。
2. ログイン後、右上の「＋」ボタン→「New repository」を選びます。
3. 「Repository name」に `vehicle-report` のような好きな名前を入力し、「Create repository」を押します（他の項目はそのままでOK）。
4. 作成された画面の中にある「uploading an existing file」というリンクをクリックします。
5. お手元の `vehicle-report` フォルダの中身（`node_modules` フォルダと `.next` フォルダは含めないでください）を、画面にまとめてドラッグ＆ドロップします。
6. 下の方にある緑色の「Commit changes」ボタンを押します。

### 手順2：Vercelにアプリを取り込む

1. [https://vercel.com/](https://vercel.com/) にアクセスし、「Continue with GitHub」でアカウントを作ります（手順1と同じGitHubアカウントでログインします）。
2. 「Add New...」→「Project」を選びます。
3. 先ほど作った `vehicle-report` のリポジトリを探して「Import」を押します。
4. 設定画面はそのままで構いませんので、「Deploy」を押します（この時点では一度失敗しますが問題ありません。次の手順に進んでください）。

### 手順3：データの保存先（Prisma Postgres）を接続する

以前あった「Vercel Postgres」というサービスは終了し、現在は「Prisma Postgres」というサービスに変わっています。

1. Vercelのプロジェクト画面上部にある「Storage」タブを開きます。
2. 「Connect Database」または「Create Database」のようなボタンを押します。
3. 一覧の中から「Prisma」（Prisma Postgres）を選びます。
4. 案内にしたがって「Continue」を押し、リージョン（地域）とプラン（無料の「Free」でOK）を選び、データベースに好きな名前を付けて作成します。
5. 作成できたら、対象のプロジェクト（`vehicle-report`）に「Connect」します。
6. これで `DATABASE_URL` という設定が自動的にプロジェクトに追加されます（手入力は不要です）。

Prisma Postgresは無料の範囲（月100,000回の操作・1GBの保存容量など）が用意されており、このアプリの規模であれば十分収まります。

なお、Vercelの画面は更新されることがあるため、表示されるボタンの文言が多少異なる場合がありますが、「Storage」→「データベースを作る・つなぐ」という流れは同じです。

### 手順4：合言葉（パスワード）を設定する

インターネット上に公開すると、URLを知っている人なら誰でもアクセスできてしまいます。そのため、合言葉（パスワード）を設定します。

1. プロジェクト画面の「Settings」→「Environment Variables」を開きます。
2. 以下の2つを追加します（Key欄に名前、Value欄に値を入力し、それぞれ「Save」します）。

| Key（名前） | Value（値） | 説明 |
|---|---|---|
| `APP_PASSWORD` | 好きなパスワード（例：`mitsuwa2026`） | アプリを開くときに入力する合言葉 |
| `SEED_SECRET` | 好きなランダムな文字列（例：`setup-key-91827`） | 最初の1回だけ使う、初期データ投入用の合言葉 |

### 手順5：もう一度デプロイする

1. 「Deployments」タブを開き、一番上のデプロイの右側にある「...」→「Redeploy」を押します。
2. 数分待つと、「Ready」のような表示になり、URL（例：`https://vehicle-report-xxxx.vercel.app`）が発行されます。

### 手順6：初期データを1回だけ入れる（お試しデータが欲しい場合のみ）

ブラウザで次のようなアドレスを開きます（`あなたのURL` と `SEED_SECRETの値` はご自身のものに置き換えてください）。

```
https://あなたのURL.vercel.app/api/admin/seed?key=SEED_SECRETの値
```

「サンプルデータの投入が完了しました。」と表示されれば成功です。まっさらな状態から始めたい場合は、この手順6は行わなくて構いません（車両は「車両管理」画面から登録できます）。

### 手順7：iPhoneから開く

1. iPhoneのSafariで、手順5で発行されたURL（`https://〜.vercel.app`）を開きます。
2. 手順4で決めたパスワードを入力して「入る」を押します。
3. 表示されたら、Safariの「共有」ボタン→「ホーム画面に追加」で、いつでもアイコンから開けるようになります。

これで、Wi-Fiの種類に関係なく、外出先の車の中からでもアクセスできるようになります。
